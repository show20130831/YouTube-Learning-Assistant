# Evaluation 2026-10-14: run-to-run noise and a first model comparison (preliminary)

**Status: preliminary.** This is the first run of the evaluation pipeline (MVP). It establishes how much the
production model's results vary between identical runs, and tries one alternative model. No production change is
decided from it: the dataset is small, half of it was seen while tuning the prompt, and the blind human review of
summaries is not done yet.

## Setup

| | |
|---|---|
| Dataset | `2026-10-14.mvp`: 19 videos from 9 channels. **dev** 9 (seen while tuning the prompt), **test** 10 (never used before) |
| Labels | Topics each video substantively discusses, from the transcript, with a verbatim evidence quote per label; drafted, then confirmed by a person before any score was shown ([guidelines](../../eval/labeling-guidelines.md)) |
| Topics | The 9 topics of the production configuration (kept locally; fingerprint `b1255e343920`) |
| Prompt / rules | `2026-10-07.5` / `2026-10-08.1` |
| Runs | Production model `nvidia/nemotron-3-super-120b-a12b:free` twice, on different days (A/A); candidates `google/gemma-4-31b-it:free` and `dots-studio/dots-3-note-preview:free`; one model per run, fallback off |
| Metric | Micro-averaged precision, recall and F1 of the final topics (video × topic decisions) |
| Statistics | Paired by video: bootstrap 95% CI (10,000 resamples of videos), permutation test, exact McNemar, Clopper-Pearson |

## Findings

All under the conditions above; with 18–19 videos, only large differences are detectable.

1. **Run-to-run noise is about ±0.09 in F1.** Running the production model twice on the same videos gave
   F1 0.69 and 0.70 (difference +0.010, 95% CI −0.062 to +0.087). A configuration change therefore has to move
   F1 by more than about 0.09 before this dataset can tell it apart from noise.
2. **The production model over-labels topics.** Recall is 1.00 (no labelled topic missed) but precision is 0.52:
   about half of the topics it attaches are not substantively discussed. The extra topics are mostly LLM
   (8 extra) and AI Agent (6 extra). In the digest this means topic tags and the trending list overstate matches.
3. **The deterministic topic rules added nothing here.** The model's own topics already contained every topic the
   title and keyword rules found (rule rescues: 0). The rules were added after earlier runs missed topics; on this
   data their benefit could not be observed, and the over-labelling is the model's.
4. **Title matching alone is precise but misses most topics** (precision 1.00, recall 0.29): the LLM is needed
   for recall, and the open problem is its precision.
5. **The candidate `dots-3-note-preview` was not better.** On the 18 videos both answered: F1 −0.048
   (95% CI −0.104 to +0.017, permutation p = 0.26), precision −0.053. The lower CI bound is below the noise
   margin (−0.087), so under the planned rule it would not replace the production model.
6. **Free model availability is the operational risk.**

   | Model | Answered | Notes |
   |---|---|---|
   | nemotron-3-super (production) | 19/19 and 18/19 | One reply hit the 180 s deadline in the second run (p50 42 s, p95 93 s) |
   | dots-3-note-preview | 18/19 | One `HTTP 400` from the provider |
   | gemma-4-31b-it (production fallback) | 0/1, three times | Upstream `429` on the first request, on two days, with the daily quota far from used |

   Gemma is the first fallback in production and failed the same way on 2026-10-08. Only a handful of free models
   with long context and structured output remain on OpenRouter (19 on 2026-10-06).

## Limitations

- 19 videos, 18 paired; per-topic counts are small, and RAG, LangGraph and Data Engineering have no labelled video.
- 9 of the 19 videos were seen while tuning the prompt; the 10 test videos alone are too few to report separately.
- One person labelled; agreement between labellers is not measured yet.
- Summary quality (contradictions, unsupported claims, missing key points) is not measured: the blind human review
  is not done yet. This report covers topics, format and availability only.
- One test video (Karpathy, 2022) is old enough that the models may have seen it in training.
- Runs were made on different days; the answering model and provider were recorded and did not change within a
  model's runs.

## Next steps

- Extend the test set to 24 videos and run the blind human review on 6 pairs (see the evaluation plan).
- Investigate the over-labelling on the **dev** videos only (a prompt change is decision B; test videos must not
  guide it), then evaluate the prompt change against the noise margin.
- Review the fallback order: if gemma keeps answering 429, a primary-model failure in production falls through
  to `openrouter/free`, whose routing is unpredictable (as happened on 2026-10-08).
